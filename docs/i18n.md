# Internationalization (i18n)

- **Engine**: `vue-i18n` v11 (`legacy: false`), default `locale` and `fallbackLocale` = `zh-CN`.
- **Key scheme**: `area.sub.element` camelCase (e.g. `launch.button.start`).
- **Locale files**: `src/locales/<locale>/<feature>.json` merged automatically via `import.meta.glob('./locales/*/*.json', { eager: true })` where the file name is the top-level namespace.
- **Backend error discipline**: Rust never emits user-facing text. All errors serialize as `AppError { code: string, params: Record<string, string>, detail?: string }` and the UI renders `t('error.' + code, params)`.
- **Formatting**: Plurals use `vue-i18n` pipe syntax. Dates, byte sizes and numbers are formatted by plain helpers (`formatBytes`/`formatDate`), not `Intl` — no `d()`/`n()`/`datetimeFormats` are configured.
- **Lint gate**: `scripts/lint-i18n.mjs` rejects CJK characters in `src/**/*.{vue,ts}` outside `src/locales/`, `*.test.ts`, and `mock.ts`, and verifies that every static `t('...')`, `$t('...')`, or `keypath="..."` exists in `zh-CN`.
- **Dynamic keys**: keys built at runtime (`t(tab.titleKey)`, `t('error.' + code)`, `t(task.titleKey)`) are **not** checked by the lint; every backend `code()` string must exist in `src/locales/zh-CN/error.json`, and every task `titleKey` in `tasks.json`.
